We need to fix and improve the IM Report / Valuation Report completeness logic, report status wording, and active listing naming.

Context:
The CSV import flow is now working correctly.

Current successful import example:
- 40 valid rows
- 40 sections matched
- 177 fields changed
- 0 unknown keys

However, after import, the IM Report screen shows:
- “40 of 40 sections have content”
- but also shows “4 required sections need content — tap to complete”

This is confusing and contradictory. If all 40 sections have imported content, the app should not say sections “need content” unless the actual section content is empty. The app needs to separate narrative section completeness from app data readiness, placeholder review, access settings, and publishing checks.

Do not break existing CSV import, report sections, valuation, equipment, leases, tours, listing, or buyer access features.

TASK 1 — Fix contradictory completeness wording

Current wording:
“4 required sections need content — tap to complete”

Replace this with:
“4 report checks need attention”

Only use “need content” when a required report section is genuinely empty.

If a section has main_body, bullet points, table_json, or chart_json content, it should count as having content.

Sections with content but placeholder wording should be marked “Needs Review”, not “Missing Content”.

Update the Report Completeness card to show clearer lines:

Example:
Report Completeness: 69%

40 of 40 sections have content
4 report checks need attention

Do not show:
“4 required sections need content”
when the section bodies are populated.

TASK 2 — Separate completeness categories

Refactor the completeness calculation so it separates:

1. Narrative Section Completeness
2. App Data Completeness
3. Structured Data Completeness
4. Buyer Access / Publish Readiness
5. Placeholder / Needs Review Checks

Suggested scoring weights:

- Report narrative sections: 35%
- Financial / valuation data: 25%
- Equipment / asset data: 10%
- Lease / premises data: 10%
- 360 tour data: 10%
- Buyer access / publish settings: 10%

The UI should be able to display something like:

Narrative: 100%
Valuation Data: 85%
Equipment: 100%
Lease: 60%
360 Tour: 100%
Buyer Access: 40%
Publishing Readiness: Needs review

The final report completeness percentage can still be one number, but the warnings must clearly explain what is missing or needs review.

TASK 3 — Create a Report Checks screen

When the user taps the orange warning card, open a Report Checks screen or modal.

Title:
Report Checks

Show positive checks:
✅ 40 / 40 sections contain text
✅ CSV import complete
✅ Valuation data available
✅ Equipment value available
✅ 360 tour data available

Show attention items:
⚠️ 4 checks need attention

Example checks:
- Replace placeholder Reason for Sale text
- Confirm buyer access settings
- Confirm due diligence document availability
- Confirm public/private visibility for financial sections

The checks should be generated dynamically from the current listing/report data.

The screen should not make the user feel the CSV import failed if it succeeded.

TASK 4 — Add placeholder detection

Add placeholder detection to report sections.

If a section body or bullets contain placeholder phrases, mark that section as needs_review.

Do not mark it as empty.

Placeholder phrases to detect, case-insensitive:

- seller should
- to be confirmed
- insert
- placeholder
- example only
- not yet provided
- replace this
- add details
- update this
- enter details
- pending
- tbc
- n/a where inappropriate
- lorem ipsum

Example:
If the Reason for Sale section says:
“The seller should use this section to clearly explain why the business is being offered for sale...”

Then:
- section_has_content = true
- section_status = needs_review
- warning = “Reason for Sale contains placeholder guidance. Replace with seller-specific wording.”

TASK 5 — Required section logic

Required sections should only be classed as “missing content” if they do not have any meaningful content in:

- main_body
- bullet_points
- table_json
- chart_json

A required section with imported content should not be counted as missing.

Required section statuses should be:

- Complete
- Needs Review
- Missing Content
- Missing App Data
- Hidden From Report
- Access Not Configured

Do not collapse all of these into “needs content”.

TASK 12 — Preserve app-generated financial data

CSV import should update narrative/report fields only.

It must not overwrite:
- Valuation figures
- Revenue sync figures
- Xero connection state
- Square connection state
- Equipment totals
- Lease analysis data
- Tour scene/pin counts
- Buyer access logs
- Division calculations

CSV can update text, bullets, tables, chart JSON metadata, section titles, subtitles, visibility, and include toggles.

TASK 13 — Publish gating

Publishing should not be blocked just because a section is “Needs Review”, unless the seller chooses strict mode.

Add publish readiness categories:

Hard blockers:
- Missing required report title/business name
- Missing valuation data
- No public/approved-buyer visibility configured
- Disclaimer missing
- Seller does not have permission

Soft warnings:
- Placeholder text detected
- Reason for sale not personalised
- Lease not uploaded
- Due diligence checklist incomplete
- Buyer access settings incomplete
- Some financial sections are hidden
- No growth opportunities added
- No risks/mitigations added

If soft warnings exist, allow publish but show:
“Publish with warnings?”

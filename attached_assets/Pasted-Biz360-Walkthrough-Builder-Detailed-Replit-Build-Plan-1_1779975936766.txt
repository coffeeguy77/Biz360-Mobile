Biz360 Walkthrough Builder — Detailed Replit Build Plan

1. Core Concept

Build a 360-degree walkthrough builder for Biz360 that allows sellers, brokers, and admins to create interactive business tours.

The system must support:

* One seller managing one business
* A broker managing multiple businesses
* Multiple 360 scenes per business
* Cloudinary-hosted 360 images, videos, thumbnails, and ElevenLabs audio
* Hotspot navigation between 360 scenes
* Information popups inside each scene
* Audio triggers per scene or per hotspot
* Ability to add more 360 images later without rebuilding the tour
* Buyer-facing walkthrough viewer
* Admin/builder interface for editing tours

The hierarchy should be:

User → Business/Cafe ID → Tour → Scene → Hotspots / Audio / Popups

2. Recommended Data Structure

Users Table

users {
  id uuid primary key
  full_name text
  email text
  role text -- seller, broker, admin, buyer
  created_at timestamp
}

Roles:

seller = can create/manage their own business
broker = can create/manage multiple businesses
admin = full platform control
buyer = can view tours they have permission to access

⸻

Businesses Table

businesses {
  id uuid primary key
  owner_user_id uuid references users(id)
  broker_user_id uuid references users(id) nullable
  business_name text
  business_type text -- cafe, restaurant, gym, salon, retail, etc.
  address text
  suburb text
  state text
  country text
  status text -- draft, live, private, archived
  created_at timestamp
  updated_at timestamp
}

Important:

A seller may own one business.

A broker may have many businesses.

Each business/cafe must have a unique business ID.

Example URL:

/biz360/cafe/:businessId/tour/:tourId

⸻

Tours Table

tours {
  id uuid primary key
  business_id uuid references businesses(id)
  title text
  description text
  cover_image_url text
  default_start_scene_id uuid nullable
  visibility text -- private, public, nda_locked, invite_only
  status text -- draft, live, archived
  created_at timestamp
  updated_at timestamp
}

Each business can have multiple tours if needed:

* Main buyer tour
* Staff training tour
* Investor due diligence tour
* Private broker tour

⸻

Scenes Table

Each 360 image becomes a scene.

tour_scenes {
  id uuid primary key
  tour_id uuid references tours(id)
  business_id uuid references businesses(id)
  title text
  description text
  scene_order integer
  panorama_url text
  panorama_public_id text -- Cloudinary public ID
  thumbnail_url text
  initial_yaw float default 0
  initial_pitch float default 0
  initial_zoom float default 50
  floorplan_x float nullable
  floorplan_y float nullable
  is_start_scene boolean default false
  created_at timestamp
  updated_at timestamp
}

Example scene titles:

Front Entrance
Customer Seating Area
Coffee Bar
Kitchen
Storage Room
Outdoor Dining
Office
Back Exit

⸻

Hotspots Table

Hotspots are clickable points inside a 360 scene.

scene_hotspots {
  id uuid primary key
  business_id uuid references businesses(id)
  tour_id uuid references tours(id)
  scene_id uuid references tour_scenes(id)
  type text -- navigation, info, audio, video, document, external_link
  title text
  description text
  yaw float
  pitch float
  icon_type text -- arrow, info, speaker, video, document, dollar, equipment
  target_scene_id uuid nullable
  popup_content jsonb nullable
  media_url text nullable
  audio_url text nullable
  video_url text nullable
  document_url text nullable
  external_url text nullable
  display_order integer
  created_at timestamp
  updated_at timestamp
}

Hotspot types:

navigation = move to another 360 scene
info = open text/image popup
audio = play ElevenLabs narration
video = play embedded video
document = open PDF/spec sheet
external_link = open another page

⸻

Audio Table

Store ElevenLabs narration references here.

scene_audio {
  id uuid primary key
  business_id uuid references businesses(id)
  tour_id uuid references tours(id)
  scene_id uuid references tour_scenes(id)
  title text
  audio_url text
  audio_public_id text -- Cloudinary public ID
  trigger_type text -- auto_on_enter, click_hotspot, manual_button
  transcript text
  duration_seconds integer
  created_at timestamp
}

Trigger types:

auto_on_enter = audio plays when entering scene
click_hotspot = audio plays when user clicks speaker/info point
manual_button = buyer presses play button

5. Buyer Viewer

Create a public/private viewer page:

/tour/:tourId

The viewer should include:

* Fullscreen 360 scene
* Clickable navigation hotspots
* Clickable info hotspots
* Audio play button
* Scene list/minimap
* Business title
* Contact seller button
* Request more info button
* NDA lock if needed

Viewer behaviour:

When buyer opens tour:

1. Load start scene
2. Display blurred thumbnail instantly
3. Load full 360 panorama
4. Show hotspots
5. If scene has auto narration, show “Play narration” prompt
6. Buyer clicks hotspots to move or learn more

Do not force autoplay audio on mobile. Use a visible play button because mobile browsers often block autoplay.

6. Adding More Information Later

The system must allow a seller/broker/admin to add:

* New 360 scene
* New hotspot inside existing scene
* New audio narration
* New popup
* New document
* New video
* New navigation connection

Example use case:

A buyer asks:

Can I see the back storage area?

The seller can:

1. Upload a new 360 photo called “Back Storage Room”
2. Add it to the existing tour
3. Open the “Kitchen” scene
4. Add a navigation hotspot pointing to “Back Storage Room”
5. Add an info popup about stock capacity
6. Save and publish

No rebuild required.

9. Cloudinary Upload Flow

The app should not upload directly through the frontend using secret keys.

Use a secure backend upload signature.

Flow:

1. Frontend requests upload signature from backend
2. Backend signs Cloudinary upload
3. Frontend uploads file to Cloudinary
4. Cloudinary returns secure URL and public ID
5. App stores URL and public ID in database

Required environment variables:

CLOUDINARY_CLOUD_NAME=
CLOUDINARY_API_KEY=
CLOUDINARY_API_SECRET=

⸻

10. ElevenLabs Audio Flow

Option A — Manual Upload MVP:

1. Seller creates narration in ElevenLabs
2. Downloads MP3
3. Uploads MP3 to Biz360
4. Biz360 stores MP3 in Cloudinary
5. Seller attaches audio to scene or hotspot

This is easiest for MVP.

Option B — API Integration Later:

1. Seller writes narration script in Biz360
2. Selects voice
3. Biz360 sends text to ElevenLabs API
4. ElevenLabs returns generated audio
5. Biz360 uploads audio to Cloudinary
6. Audio becomes available in builder

For MVP, build Option A first.

16. Critical UX Details

The builder must be simple.

The seller/broker should not think in technical terms like yaw and pitch.

They should only do this:

1. Upload a 360 image
2. Name the scene
3. Click where they want a hotspot
4. Choose what the hotspot does
5. Save
6. Preview tour

For the buyer, the tour should feel like:

Click arrow → move forward
Click info icon → learn more
Click speaker → hear owner explain
Click document → verify detail

17. Replit Build Prompt

Build a full-stack Biz360 Walkthrough Builder web app.

The app must allow sellers, brokers, and admins to create interactive 360-degree walkthrough tours for businesses.

The system must be user and business based.

Data hierarchy:

User → Business → Tour → Scene → Hotspot / Audio / Popup

A seller can manage their own business.
A broker can manage multiple businesses.
An admin can manage everything.
A buyer can view tours and request more information.

Use React for the frontend, Node/Express for the backend, PostgreSQL for the database, and Cloudinary for media storage.

Use a 360 panorama viewer such as Photo Sphere Viewer or Pannellum.

1. Authentication and roles:

* seller

4. Scene management:

* upload 360 panorama image to Cloudinary

* add title and description

* set start scene

5. 360 viewer:

* load panorama image
* allow viewer to look around
* show hotspots at saved yaw/pitch coordinates
* support mobile and desktop

6. Hotspot builder:

* allow seller/broker/admin to click inside the 360 viewer to place a hotspot
* save yaw and pitch coordinates
* allow hotspot type selection:
    * navigation

    * audio

    * external link
* allow icon selection:
    * arrow

    * video

* allow info hotspot to open popup content
* allow audio hotspot to play Cloudinary-hosted ElevenLabs MP3
